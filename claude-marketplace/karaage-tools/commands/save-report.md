# save-report

現在の会話の中でClaudeが生成した調査結果・回答を、Obsidian Vault（`~/Developer/obsidian`）にMarkdownレポートとして保存する。

## ワークフロー

### Step 1: 会話内容の整理

現在の会話コンテキストから、引数「$1」に関連する以下の情報を抽出・整理する:

- **調査結果・回答の要約**: Claudeが生成した主要な回答・分析を簡潔にまとめる
- **詳細内容**: 調査で得られた具体的な情報、コード例、手順など
- **ソース情報**: 参照したURL、ファイルパス、使用したツール（WebSearch, ask-gemini, x-search等）の結果

引数が省略された場合は、会話全体のテーマを推測してトピックを自動決定する。

### Step 2: 保存先フォルダの決定

**新しいフォルダは作成しない。** Obsidian Vault（`~/Developer/obsidian`）内に既に存在するフォルダの中から、レポートの内容に最も適したものを選んで配置する。

1. まず Vault 直下のフォルダ一覧を取得する（例: `ls -d ~/Developer/obsidian/*/`）。階層は1階層までを対象とする。
2. 取得したフォルダ名と、レポートの内容（技術調査・バグ修正・設計・ツール・学習など）を照らし合わせ、最も近い既存フォルダを選択する。
3. 明確に該当するフォルダが無い場合は、最も汎用的・近い既存フォルダ（例: `Reports/` など汎用フォルダがあればそれ）を選ぶ。それも無ければ Vault 直下に直接配置する。

いずれの場合も、存在しないフォルダ名を指定して新規作成することはしない。

### Step 3: ファイル名の生成

以下の形式でファイル名を生成する:

```
YYYY-MM-DD_<トピックのスラッグ>.md
```

- 日付は本日の日付
- スラッグは日本語で記述する（例: `Reactサーバーコンポーネント概要`）

### Step 4: レポートの作成

Writeツールで以下のフォーマットのMarkdownファイルを作成する。基本はMarkdownで記述し、表現力が必要な箇所（表組み・定義リスト・注釈・レイアウト調整など）では部分的にHTMLを使用してよい:

```markdown
---
created: YYYY-MM-DD
topic: "<トピック>"
source: "Claude Code"
tags:
  - <関連タグ1>
  - <関連タグ2>
---

# <トピックのタイトル>

## 要約

[調査結果・回答の要約を3-5文で]

## 詳細

[調査で得られた具体的な情報、分析、コード例、手順など]
[会話内での主要な発見や結論を構造化して記述]

## ソース

- [参照したURL、ドキュメント、ファイルなどのリスト]
- [使用したツール（WebSearch, Gemini, X検索等）とその結果の要約]

## メモ

[補足事項、今後の TODO、関連するトピックへのリンクなど]
```

### Step 5: 保存完了の報告

ファイル作成後、以下を表示する:

```
✅ レポートを保存しました
📁 <保存先のフルパス>
📝 <トピックタイトル>
```

## 注意事項

- Obsidian のフロントマター（YAML）を必ず含め、Obsidian上での検索・フィルタリングを容易にする
- タグは内容から自動推定する（例: `#react`, `#debugging`, `#aws` など）
- 同名ファイルが既に存在する場合はサフィックス（`_2`, `_3`...）を付けて重複を回避する
- コードブロックは言語指定を付ける（```js, ```python など）
- 会話中に画像やスクリーンショットがあった場合は、その説明をテキストで記載する（画像ファイル自体はコピーしない）
