# save-report

現在の会話の中でClaudeが生成した調査結果・回答を、Obsidian Vault（`~/Developer/obsidian`）にMarkdownレポートとして保存する。

## ワークフロー

### Step 1: 会話内容の整理

現在の会話コンテキストから、引数「$1」に関連する以下の情報を抽出・整理する:

- **調査結果・回答の要約**: Claudeが生成した主要な回答・分析を簡潔にまとめる
- **詳細内容**: 調査で得られた具体的な情報、コード例、手順など
- **ソース情報**: 参照したURL、ファイルパス、使用したツール（WebSearch, ask-gemini, x-search等）の結果

引数が省略された場合は、会話全体のテーマを推測してトピックを自動決定する。

### Step 2: 保存先フォルダの決定

レポートの内容に応じて、以下の基準で保存先フォルダを選択する:

| 内容の種類 | 保存先 | 例 |
|-----------|--------|-----|
| 技術調査・ライブラリ比較・API仕様 | `Tech/` | フレームワーク比較、API調査 |
| バグ修正・トラブルシューティング | `Debugging/` | エラー解決、設定問題 |
| 設計・アーキテクチャの検討 | `Architecture/` | DB設計、システム構成 |
| ツール・環境構築 | `Tools/` | CLI設定、開発環境 |
| 学習・知識整理 | `Learning/` | 概念の理解、チュートリアル |
| その他・分類不明 | `Reports/` | 汎用レポート |

保存先フォルダが存在しない場合は自動で作成する。

### Step 3: ファイル名の生成

以下の形式でファイル名を生成する:

```
YYYY-MM-DD_<トピックのスラッグ>.md
```

- 日付は本日の日付
- スラッグはトピックを英語のkebab-caseに変換（例: `react-server-components-overview`）
- 日本語トピックは意味を保って英訳する

### Step 4: レポートの作成

Writeツールで以下のフォーマットのMarkdownファイルを作成する:

```markdown
---
created: YYYY-MM-DD
topic: "<トピック>"
source: "Claude Code"
tags:
  - <関連タグ1>
  - <関連タグ2>
---

# <トピックのタイトル>

## 要約

[調査結果・回答の要約を3-5文で]

## 詳細

[調査で得られた具体的な情報、分析、コード例、手順など]
[会話内での主要な発見や結論を構造化して記述]

## ソース

- [参照したURL、ドキュメント、ファイルなどのリスト]
- [使用したツール（WebSearch, Gemini, X検索等）とその結果の要約]

## メモ

[補足事項、今後の TODO、関連するトピックへのリンクなど]
```

### Step 5: 保存完了の報告

ファイル作成後、以下を表示する:

```
✅ レポートを保存しました
📁 <保存先のフルパス>
📝 <トピックタイトル>
```

## 注意事項

- Obsidian のフロントマター（YAML）を必ず含め、Obsidian上での検索・フィルタリングを容易にする
- タグは内容から自動推定する（例: `#react`, `#debugging`, `#aws` など）
- 同名ファイルが既に存在する場合はサフィックス（`_2`, `_3`...）を付けて重複を回避する
- コードブロックは言語指定を付ける（```js, ```python など）
- 会話中に画像やスクリーンショットがあった場合は、その説明をテキストで記載する（画像ファイル自体はコピーしない）
